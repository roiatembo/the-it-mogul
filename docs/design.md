# The IT Mogul — Design Direction

## 1. Design objective

The website should feel like a serious, technically capable company that builds digital products and business systems.

It should NOT look like:

- A cheap local web-design business
- A generic WordPress freelancer website
- A SaaS template
- An overly corporate enterprise website
- A portfolio that prioritizes visual effects over communication

The desired impression is:

**Technical. Confident. Modern. Human. Precise.**

The visitor should feel that The IT Mogul understands both technology and business.

---

## 2. Primary design reference

Primary reference:

https://www.moritzdunkel.de/

Use this website as inspiration for:

- Information hierarchy
- Sales-oriented page structure
- Problem → solution storytelling
- Clear service presentation
- Strong typography
- Generous whitespace
- Large section headings
- Portfolio presentation
- Social proof
- Founder/personality section
- Process explanation
- FAQ
- Repeated but controlled calls to action

The reference website successfully moves the visitor from understanding a problem to understanding the solution and eventually taking action.

Do NOT copy:

- Branding
- Logo
- Text
- Images
- Illustrations
- Exact layouts
- Exact typography
- Proprietary assets
- Exact animations
- Exact visual identity

Create an original visual identity for The IT Mogul.

---

## 3. Visual personality

The website should feel:

### Technical

Use visual language that suggests software engineering, systems, infrastructure and precision without turning the website into a developer portfolio.

### Premium

Use strong typography, spacing, composition and restraint rather than excessive gradients, shadows or decorative effects.

### Human

The IT Mogul should feel like a real company run by real people rather than an anonymous software corporation.

### Confident

Headlines can be bold and direct.

Avoid timid language such as:

- "We try to..."
- "We can potentially..."
- "We offer a range of..."

Prefer confident statements that are supported by the actual service.

### Practical

The website should consistently connect technology to business outcomes.

---

## 4. Layout philosophy

Use a strong editorial layout.

Prioritize:

- Large headlines
- Clear visual hierarchy
- Generous whitespace
- Strong alignment
- Controlled content width
- Large visual sections
- Intentional asymmetry where appropriate
- Clear transitions between sections

Avoid:

- Dense layouts
- Endless cards
- Excessive rounded containers
- Every section being placed inside a card
- Excessive borders
- Decorative UI that does not communicate anything
- Stock-photo-heavy layouts

Not every section needs a background colour or card.

Use whitespace as a design element.

---

## 5. Typography

Typography should be one of the strongest visual elements.

Use:

- A distinctive modern sans-serif typeface
- Large display typography for major headings
- Highly readable body text
- Strong contrast between headings and supporting copy

Headlines should be allowed to occupy substantial visual space.

Use responsive typography through `theme.json` and fluid sizing where appropriate.

Avoid using too many font families or weights.

Typography should communicate confidence and technical sophistication rather than corporate bureaucracy.

---

## 6. Colour

The colour system should be restrained.

The base should primarily use:

- A strong neutral background
- A strong contrasting text colour
- One distinctive brand accent
- Optional secondary neutral tones

Do not build the design around multiple gradients or a rainbow palette.

The accent colour should be used intentionally for:

- Primary CTAs
- Links
- Important highlights
- Small interactive details
- Selected states

The design should remain visually strong even when the accent colour is removed.

Final colour values should be established in `theme.json`.

---

## 7. Navigation

Navigation should be simple.

Recommended primary navigation:

- Services
- Work
- About
- Insights
- Contact

A prominent CTA should be visible in the header.

The navigation should not attempt to expose every page.

Use dropdowns only when they genuinely improve navigation.

On mobile, the navigation should be simple and easy to operate.

---

## 8. Homepage structure

The homepage should follow a persuasive narrative.

Recommended structure:

### 01 — Hero

Immediately communicate:

- What The IT Mogul does
- Who it helps
- Why it matters

Example direction:

**Websites. Software. Systems that work.**

Supporting copy should explain that The IT Mogul builds, fixes and improves digital systems for businesses.

Primary CTA:

**Start a project**

Secondary CTA:

**See our work**

The hero should establish technical credibility without becoming overly technical.

---

### 02 — Trust / credibility

Immediately establish credibility after the hero.

Possible elements:

- Years of experience
- Technologies
- Selected clients
- Projects completed
- Relevant certifications
- Client logos
- Short credibility statement

Only use factual claims that can be supported.

Never fabricate statistics, clients or testimonials.

---

### 03 — Problems

Use a problem-first section inspired by the reference website.

Headline direction:

**Your website shouldn't be another problem to manage.**

Potential problems:

- Your website looks outdated.
- Your site isn't generating enquiries.
- WordPress keeps breaking.
- Your website is slow.
- Customers cannot easily buy from you online.
- Too much of your business is handled manually.
- Your systems do not communicate with each other.
- You are difficult to find on Google.

This section should make the visitor recognize their own situation.

---

### 04 — Solution

Transition from problems to the solution.

Explain that The IT Mogul doesn't simply build websites.

We build digital systems that help businesses:

- Attract customers
- Sell online
- Improve visibility
- Automate repetitive work
- Operate more efficiently
- Maintain a reliable online presence

---

### 05 — Services

Present services as solutions rather than a generic service list.

Primary service categories:

**Build**

Websites & E-commerce

**Fix**

WordPress Troubleshooting & Technical Support

**Grow**

SEO & Website Optimization

**Automate**

Custom Software & Business Automation

**Maintain**

Website Care & Technical Support

Each service should communicate:

- The problem
- What we do
- The outcome
- A link to learn more

---

### 06 — Selected work

Show real projects.

Prioritize quality over quantity.

Each project should communicate:

- Client
- Problem
- What was built
- Technology where useful
- Result where measurable

Use large visual project previews rather than tiny portfolio cards.

The portfolio should feel like evidence of engineering capability.

---

### 07 — Why The IT Mogul

Explain the company's difference.

Potential themes:

- Engineering-first approach
- Direct communication
- Practical solutions
- No unnecessary technology
- Ability to work with existing systems
- Websites and software under one roof
- Long-term technical support

This section should answer:

**"Why should I hire you instead of another developer or agency?"**

---

### 08 — About / Founder

The website should introduce the person behind the business.

The tone should be personal but professional.

Explain:

- Who Roia is
- How The IT Mogul started
- Experience
- Engineering background
- Philosophy
- Why the company exists

The reference website demonstrates how personality can build trust without making the site feel less professional.

---

### 09 — Process

Show a simple project process.

Example:

**01 — Tell us what you need**

We understand your business, problem and goals.

**02 — Plan**

We recommend the right solution, scope and approach.

**03 — Build**

Design, development, integrations and testing.

**04 — Launch**

Final checks, deployment and handover.

**05 — Improve**

Ongoing maintenance, SEO, support and development.

The process should reduce perceived risk.

---

### 10 — Testimonials / proof

Use genuine testimonials only.

If there are insufficient testimonials, prioritize:

- Case studies
- Portfolio projects
- Before/after examples
- Client logos
- Measurable project outcomes
- Technical credibility

Do not create fake reviews to make the section look complete.

---

### 11 — FAQ

Answer questions that prevent people from contacting the company.

Potential questions:

- How much does a website cost?
- How long does a website take?
- Do you work with international clients?
- Do you work with existing WordPress websites?
- Can you maintain a website after launch?
- Can you build custom software?
- Can you integrate existing business systems?
- Do you provide SEO?
- What happens after I contact you?

---

### 12 — Final CTA

End with a strong, simple invitation.

The visitor should know exactly what to do.

Possible direction:

**Have a project in mind?**

Tell us what you're trying to build, fix or improve.

CTA:

**Start a project**

Secondary:

**Contact us**

---

## 9. Animation

Animation should be subtle and purposeful.

Use animation for:

- Page transitions
- Hover states
- Image reveals
- Small entrance animations
- Navigation interactions
- Portfolio interactions

Avoid:

- Excessive parallax
- Constant movement
- Large distracting animations
- Animation that delays content
- Animation that harms accessibility
- Animation that exists only to demonstrate technical ability

Respect `prefers-reduced-motion`.

---

## 10. Images

Prefer real project imagery and screenshots.

For portfolio work:

- Use actual screenshots
- Use device/browser mockups only when useful
- Show enough of the work to communicate quality

Avoid generic stock photography whenever possible.

If stock imagery is necessary, it should support the message rather than simply fill space.

---

## 11. Responsive design

Design mobile-first.

The website must work exceptionally well at:

- Mobile
- Tablet
- Laptop
- Large desktop

Do not simply shrink the desktop layout.

Reconsider:

- Typography
- Spacing
- Navigation
- Grid layouts
- Image crops
- CTA placement
- Section ordering

for smaller screens.

---

## 12. Accessibility

Accessibility is part of the design.

Ensure:

- Sufficient colour contrast
- Keyboard navigation
- Visible focus states
- Semantic HTML
- Correct heading hierarchy
- Descriptive link text
- Meaningful image alt text
- Accessible forms
- Reduced-motion support
- Adequate touch targets

Do not sacrifice accessibility for visual effects.

---

## 13. Performance

The visual design must not compromise performance.

Prefer:

- CSS over JavaScript where possible
- Optimized images
- Responsive images
- Lazy loading where appropriate
- Minimal dependencies
- Minimal frontend JavaScript
- Efficient CSS
- Native WordPress capabilities

Do not add libraries simply to implement small animations or interactions.

---

## 14. Overall design test

Before considering a page finished, ask:

1. Does it immediately communicate what The IT Mogul does?
2. Does it look credible enough for an international client?
3. Does it feel technically capable without looking like a developer portfolio?
4. Does the page guide the visitor toward an action?
5. Does every major section have a purpose?
6. Does the design work without excessive decoration?
7. Does it still look excellent on mobile?
8. Does it feel like The IT Mogul rather than a copy of another agency?
